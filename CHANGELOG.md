## [Unreleased]

### Bug Fixes

#### Boss Zhipin — login state false positive (dual credential stores)

- **Root cause:** Boss has two independent login state stores: local `~/.boss-agent/auth/session.enc`
  and browser cookies in the dedicated Chrome profile. `boss status` / `status --live` **only validates
  the former** (a legacy credential store from the Bridge/httpx era), while `existing-browser`
  strict-CDP mode searches actually use browser cookies. When "local store has stale credentials +
  browser is not logged in", `boss status` reports `logged_in: true`, causing the Agent to skip login
  and search directly — hitting `AUTH_EXPIRED`. The old runbook also forbade treating `_security_check`
  as a "not logged in" signal, which together pushed the Agent toward the wrong "anti-bot slider" branch.
- **Fix:** `check()` adds a 4th read-only probe layer `_cdp_zhipin_login_cookie()`, using a minimal
  WebSocket client built from pure stdlib to directly query the CDP browser (`Storage.getCookies`) for
  the zhipin `wt2` cookie — **browser is ground truth**. No new dependencies, no browser launch, no search.
  No wt2 → clearly reports "browser not logged in, search will return AUTH_EXPIRED" and directs to
  "user logs in + `login --cdp`"; probe failure → reports "login state unknown"; security challenge
  message also includes the browser cookie status.
- **Runbook correction:** Removed the misleading rule "only trust `boss status` for login state";
  replaced with the doctor browser cookie probe as ground truth. After launching the dedicated Chrome,
  **force a pause for the user to visually confirm** login state. `AUTH_EXPIRED` is designated as
  ground truth (go straight to the login flow; do not interpret as a security challenge);
  `_security_check` is only treated as a slider when `AUTH_EXPIRED` is absent.

### Features

#### Boss Zhipin channel

- New `boss` channel: search jobs and fetch full JDs via boss-agent-cli + CDP Chrome.
- `check()` four-layer read-only probe (is boss-agent-cli installed → is port 9222 reachable → are
  there zhipin tabs → does the browser have a `wt2` login cookie).
- Scraping uses the public API (`search_jobs` + `job_card_browser` + `browser_source="existing-browser"`).
- `agent-reach install --system --channels=boss` installs the pinned upstream boss-agent-cli
  (PRs #403–#407 merged into master); switch to a version constraint after an official release.
- Skill and install guide support "help me configure Boss Zhipin": Agent launches a dedicated Chrome
  bound to loopback only, user handles login manually, Agent validates login state and CDP pipeline.
- Pinned dependency updated from fork snapshot `8ff6bd3` to upstream commit `4c991b7` (#403–#407
  merged into master): logged-in CDP sessions can be reused directly; searches can use
  `--browser-source existing-browser` to prevent headless fallback.
- code 37 classified by original text: environment anomaly → `ENVIRONMENT_RISK`, stop immediately;
  only explicit token/stoken expiry allows a single refresh. Dedicated Chrome profile should be
  reused long-term and called at reduced frequency.

## [1.3.1] - 2026-03-27

### Bug Fixes

#### Xueqiu — comprehensive fixes

- **Fixed root cause of 400 errors:** `_ensure_cookies()` visiting only the homepage can only get
  `acw_tc` (anti-DDoS token); `xq_a_token` is dynamically generated by Xueqiu's frontend JS and
  cannot be obtained via plain HTTP. Added a three-level cookie loading strategy: ① read config file
  (saved by `--from-browser`) → ② automatically extract from local Chrome (requires browser-cookie3)
  → ③ homepage fallback.
- **Fixed User-Agent:** `"agent-reach/1.0"` was rejected by Xueqiu's anti-scraping system; switched
  to a real Chrome UA.
- **Fixed missing `Referer` header:** All API requests now include `Referer: https://xueqiu.com/`.
- **Fixed `get_hot_posts()` endpoint:** Old endpoint `/statuses/hot/listV3.json` was deprecated
  (returned empty body); switched to `/v4/statuses/public_timeline_by_category.json` with correct
  parsing of the `item.data` JSON string to get author/likes/text.
- **Fixed `urllib.request.quote` → `urllib.parse.quote`:** Using the correct module explicitly.
- **Fixed `configure --from-browser` not extracting Xueqiu cookies:** Added Xueqiu to `PLATFORM_SPECS`;
  only saves when `xq_a_token` is present.
- **Corrected misleading docs:** README/SKILL.md "no configuration needed"/"public API, no login
  required" → accurate description that a browser cookie is required.
- **Improved error messages:** `check()` failure now suggests `configure --from-browser chrome` instead
  of "may need a proxy".
